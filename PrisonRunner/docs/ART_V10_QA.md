# 무한옥 V10 최종 검수

2026년 10월 5일 Unity 6000.3.10f1 Windows에서 검수했다. 실제 캐릭터와 독방 공간 변경, 발 접지, 화면별 기획서를 대상으로 한다.

## 결과

- EditMode 42개 통과, 실패 0개. `Unity/Logs/MuhanokEditModeV10.xml`.
- 최종 PlayMode 22개 통과, 실패 0개. `Unity/Logs/MuhanokPlayModeV10Final.xml`. 감방 원숭이 배치와 대기 동작, Humanoid 발 위치, 수레에서 IK 해제, 경로 경사와 기존 그래픽 예산을 포함한다.
- `ArtV10Upgrade.log`의 `MUHANOK_V10_PASS`: 철창 독방, 잠긴 문, 청크별 원숭이 2명과 발 접지 적용.
- `ArtV10Build.log`의 `MUHANOK_BUILD_PASS`: Windows 빌드 성공, 빌드 보고서 242,013,499 bytes.
- `ArtV10RuntimeSmoke.log`의 `MUHANOK_RUNTIME_SMOKE_PASS`: 로딩 인트로에서 직접 플레이, 바닥 감속, 120개 청크, 한 번 충돌 종료, 결과와 재시작 확인.
- 실제 GPU 캡처 54장 확인: 1280×720 38장, 1702×726 8장, 1024×768 8장. 프레임 검수는 빈 화면과 다른 화면 비율의 여백을 검사하며 최종 아트 품질에 대한 판정은 아니다.
- 최종 근접 사진 3장은 별도로 재촬영했다. `ArtV10Details.log`에 발 접촉 2개와 IK 가중치 계산의 잔여 침투량 약 0.00163 m가 기록된다. 이는 특정 검수 자세의 진단값이며 모든 동작의 실제 발 메시 침투량 측정을 의미하지 않는다.
- 화면별 Word 기획서: 21페이지, 실제 화면 사진 20장, 동작별 판정 표 1개. 최종 렌더의 모든 페이지를 열어 한글 글리프, 사진 비율, 페이지 끝, 표와 본문 배치를 확인했다.
- `ArtV10Interactive.log`의 `MUHANOK_EDITOR_READY`와 `MUHANOK_GAME_VIEW_FIT`: 최종 게임 씬을 Unity Play로 열고 1280×720 화면 맞춤을 확인했다. Package Manager의 Asset Store 인증 오류는 남아 있으며 게임 Play 진입과는 별도다.

## 시각 확인

침대, 담요, 벤치와 물그릇은 철창 뒤 방 안에 있다. 원숭이는 중앙 복도 바깥의 잠긴 독방에서 고개와 팔을 움직인다. 뒷벽과 칸막이, 천장으로 방을 둘러싸고 조명으로 깊이를 구분한다. `CellCloseup`은 제작 검수용 카메라이며 일반 게임은 1인칭이다.

원숭이 손목과 허리 밴드, 0723 등번호, 손발톱은 실제 Blender 모델에 있다. 점프와 수레에서는 바닥 보정을 해제한다. `CharacterContact`도 별도 검수 카메라로 촬영했다. 로딩 사진은 사용자가 제공한 그림이며, 문서에서는 실제 게임 모델 사진과 구분했다.

## 제한

현재 자체 캐릭터는 로딩 그림의 캐릭터와 동일한 모델이 아니다. 무료 Asset Store 경찰의 다운로드 인증 문제는 이전 버전과 같이 미해결이며, 화면의 경찰은 자체 모델이다. 서브웨이 서퍼스·템플런의 최종 그래픽 품질을 달성했다고 판정하지 않았다. 손가락 그립과 보행 타이밍, 캐릭터 실루엣과 조명은 추가 아트 작업 대상이다. 접지 IK는 짧은 범위의 보정이다. 웹캠을 이용한 실제 운동 정확도나 실제 칼로리 소비량은 이번 자동 검수 범위에 포함하지 않았다.

## 바로 실행

Unity 메뉴 `Muhanok/Play GameScene` 또는 `Builds/Windows/Muhanok.exe`를 사용한다. A/D 좌우 이동, Space 점프, S 숙이기, W 하이니다. 수레에서는 A/D가 몸 기울이기다. 최종 기획서는 `docs/무한옥_화면별_게임기획서_V10.docx`, 실제 화면 갤러리는 `docs/previews/ArtV10/index.html`이다.

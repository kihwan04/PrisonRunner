# 몸동작 인식과 조작

기준일: 2026-10-26. 웹캠 몸동작은 **Unity 내부 BlazePose + Unity AI Inference**로 처리합니다. Python PoseServer나 UDP/WebSocket 연결은 사용하지 않습니다. Python 얼굴 로그인 서버와는 별도 기능입니다.

## 플레이 방식

| 방식 | 카메라에 보일 범위 | 좌우 | 점프 | 숙이기 | 하이니 |
| --- | --- | --- | --- | --- | --- |
| 전신 | 어깨~발 | 실제 몸을 좌우 구역으로 이동 | 실제 점프 | 상체 낮추기 | 한쪽 무릎 높이 들기 |
| 상체 | 허리 위 | 상체 좌우 이동 | 두 손을 머리 위로 | 상체 숙이기 | 팔 번갈아 크게 흔들기 |
| 키보드 | 카메라 불필요 | A/D·좌우 화살표 | Space | S·아래 | W·위 |

레인은 몸 위치에 맞춰 바뀝니다. 수레 갈림길의 선택 구간에서는 사이드스텝으로 실제 차선을 선택하고, 선택 확정 뒤에는 하차할 때까지 다른 레일로 이동할 수 없습니다. 일반 단선 수레에서는 좌우 균형/기울이기를 사용합니다. 키보드 C는 갈림길에서 가운데입니다.

## 시작과 보정

탈출 준비에서 방식을 고르고 카메라 미리보기와 관절선을 확인합니다. 시작하기를 누른 뒤 로딩 중 가운데에 가만히 서면 자동 보정합니다. 움직이면 보정을 다시 시도합니다. 사람이 오래 사라지면 다시 보정하며 R로도 재보정할 수 있습니다.

짧은 추적 손실, 숙이기 직전/직후의 동작 충돌, 반복 점프를 처리하는 유지 시간과 신뢰도 조건이 있습니다. 값은 `Unity/Assets/Game/Content/Data/GameSettings.asset`의 **Camera / Motion**에서 조정합니다. 기본 카메라 요청은 640×480, 30fps이며 실제 지원 해상도는 장치에 따라 달라집니다.

## 코드와 모델

```text
WebCamTexture → PoseImageSampler.compute → BlazePose 검출/랜드마크
→ One Euro 관절 필터 → PoseFrame(33개 관절)
→ Domain/MotionClassifier → Infrastructure/Pose/PoseInput
→ MotionCommand → InputRouter → 캐릭터
```

`Unity/Assets/Game/PoseInference/`가 GPU 추론을 담당합니다. 모델은 `Content/Pose/Resources/MuhanokPose/`에 있고 기본 full 모델과 가벼운 lite 모델을 선택할 수 있습니다. 사람을 놓쳤을 때 검출기를 다시 사용하고 추적 중에는 직전 결과로 다음 영역을 정합니다.

## 손으로 메뉴 선택

손을 들어 움직이면 초록 커서가 나옵니다. 버튼 위에 0.75초 머무르면 선택하며 테두리와 원형 진행 표시로 확인할 수 있습니다. 손을 내리거나 버튼을 벗어나면 선택 진행을 취소합니다. 한 번 선택한 버튼은 손을 뗐다가 다시 올려야 다시 선택합니다. 좌우 어느 손이든 사용하며, 사용 중인 손을 유지해 커서가 갑자기 반대 손으로 이동하지 않게 했습니다.

타이틀 시작 안내·메뉴·일시정지·결과·설정에 적용합니다. 설정의 위/아래 버튼으로 스크롤할 수 있습니다. 이름과 수치의 직접 입력은 키보드를 사용합니다. 웹캠 손목 위치로 가상 버튼을 선택하는 방식이며 실제 접촉·손가락 핀치·깊이 센서를 사용하는 기능은 아닙니다. 실제 손동작 감도는 실물 웹캠으로 추가 확인해야 합니다.

## 아이폰·안드로이드 카메라

설정 → 몸동작 → 아이폰·안드로이드 연결 방법에서 안내를 확인합니다. 휴대폰을 연결한 뒤 카메라 다시 검색 → 웹캠 선택 → 자세 다시 맞추기 순서입니다. Windows 카메라로 등록된 장치를 같은 Unity WebCamTexture 경로로 읽습니다. 게임 내부에 휴대폰 USB 전송 앱이나 드라이버를 내장한 것은 아닙니다.

- 아이폰 + Windows: 예를 들어 PC의 Camo Studio와 iPhone의 Camo Camera를 설치하고 데이터 USB 케이블로 연결합니다. 기기 신뢰를 승인하고 두 앱에서 영상이 보이는 상태로 게임의 카메라 목록에서 Camo를 선택합니다. 별도 앱은 이 프로젝트에 포함하거나 자동 설치하지 않습니다. [Camo 공식 연결 안내](https://camo.com/support/camo/camo-getting-started).
- 안드로이드: USB 설정에 웹캠 모드가 있는 기기는 그 모드를 선택합니다. 제조사·기종별 지원이 다르므로 모든 안드로이드에서 가능하다고 가정하지 않습니다. [Android UVC 구현](https://source.android.com/docs/core/camera/webcam), [Pixel 공식 안내](https://support.google.com/pixelcamera/answer/14274129?hl=en).
- USB 웹캠 모드가 없으면 Android용 연결 앱과 PC의 가상 카메라 드라이버가 필요합니다. Windows 11의 연결된 카메라 기능은 별도 기기 연결/권한 설정을 사용하는 대안입니다. [Microsoft 공식 안내](https://support.microsoft.com/en-us/windows/apps/phonelink/use-your-mobile-device-s-camera).
- Apple 연속성 카메라는 Mac용 기능입니다. 현재 제공하는 게임은 Windows 실행본이며 Mac 실행본이나 iOS/Android 전용 앱을 만든 것은 아닙니다. [Apple 공식 안내](https://support.apple.com/en-ie/102546).

휴대폰의 회전·미러·지연·연결 끊김과 실제 지원 여부는 장치에서 검수해야 합니다. 몸동작은 게임 PC에서 추론하며 휴대폰 카메라를 사용한다고 중앙 얼굴 서버가 필요한 것은 아닙니다.

## 운동량과 얼굴 프로필

몸무게가 있고 실제 활동이 인식된 시간에 전신 4 MET, 상체 2.5 MET 가정으로 예상 칼로리를 계산합니다. 키보드 입력, 추적 손실과 일시정지 시간을 운동 칼로리로 적립하지 않습니다. 목표는 1~5000 kcal로 직접 입력하며 달성 후에도 플레이는 계속됩니다. 의료 측정값이 아닙니다.

얼굴 로그인은 선택 사항입니다. 얼굴 프로필과 운동 기록은 연결된 서버 DB를 사용하며 서버 주소·배포는 [Docker 안내](../Services/Identity/README_DOCKER.md), 저장 위치는 [아키텍처](ARCHITECTURE.md)를 확인하세요. 거리 랭킹·지갑·화면 설정은 각 게임 PC에 남습니다. Ctrl+F10은 개발자/전시 모드에서만 오늘 기록을 초기화합니다. 메뉴 화면은 [UI 안내](GAME_FLOW_UI.md)를 확인하세요.

## 실물 확인 순서

1. Unity에서 **Mongscape → Play GameScene** 또는 최신 EXE를 실행합니다.
2. 전신 방식으로 좌우·반복 점프·숙이기 유지·무릎 들기를 확인합니다.
3. 상체 방식으로 좌우·두 손 들기·숙이기·팔 흔들기를 확인합니다.
4. 수레 갈림길에서 선택/확정/하차 뒤 조작 복구를 확인합니다.
5. 카메라를 가렸다가 다시 보였을 때 재보정과 잘못된 동작 발생 여부를 확인합니다.
6. 키보드 달리기에서는 카메라가 꺼지는지 확인합니다. 손 메뉴가 켜져 있으면 메뉴·일시정지에서는 카메라가 필요합니다. 설정에서 손 메뉴를 끌 수 있습니다.

최신 컴파일·규칙 테스트 범위는 [진행 상태](PROGRESS.md)에 있습니다. 실제 웹캠·본인 얼굴 검증은 아직 하지 않았습니다. 과거 판정 튜닝 기록은 [보관 문서](archive/history/BEFORE_2026_10_26_BODY_TRACKING.md)에 있습니다.

세 갈래 철로는 회차 내 96~120m에서 선택하고 144m부터 다음 맵 입구로 연결됩니다. 갈림길은 48m이며, 확정 후 긴 직선 구간을 제거했습니다. [경로 검수](reports/FORK_SHORT_2026_10_26.md).

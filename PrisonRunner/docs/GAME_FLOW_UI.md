# 통합 메뉴와 플레이어 데이터

`lilohdong/muhanok-test`의 기본 main 브랜치 `b2215ef`를 기존 Mongscape 소스에 통합한 화면입니다. 기존 얼굴 로그인·칼로리 목표·갈림길·경찰 연출·PostgreSQL 연결을 유지합니다.

## 화면 흐름

```text
타이틀 → 로그인 선택
          ├ 얼굴 로그인 → 얼굴 촬영 ───────────────────────────────→ 메인 ("OOO님")
          ├ 회원가입 → 저장 동의 → 닉네임(중복 확인) → 몸무게·기본 방식(건너뛰기 가능)
          │          → 얼굴 촬영 → 가입 완료 + 자동 로그인 ─────────────→ 메인 ("OOO님")
          └ 게스트 플레이 ──────────────────────────────────────→ 메인 ("게스트")
메인 메뉴
          ├ 게임 시작 → 탈출 준비(방식·목표) → 로딩 → 플레이
          ├ 거리 랭킹(전체/오늘)
          ├ 코인 상점
          ├ PC 프로필
          ├ 로그아웃(회원) / 로그인 / 회원가입(게스트) → 로그인 선택
          ├ 설정
          └ 종료
플레이 → 일시정지: 계속 / 설정 / 메인으로(기록 없이 종료)
플레이 → 결과: 거리 랭킹·칼로리·동작별 기록·최고 콤보 → 다시 / 메인으로
```

타이틀에서 입력하면 메인 메뉴 대신 **로그인 선택**(`MenuPage.Login`, `LoginGateScreen`)이 열립니다. 버튼은 마우스 클릭, 숫자키 1~3, 손 가리키기(0.9초 유지)로 고릅니다. 화면이 열릴 때마다 얼굴 서버(`GET /health`)를 확인하고, 응답이 없거나 오류이면 얼굴 로그인·회원가입 버튼을 비활성화하고 사유를 표시합니다. 게스트 플레이는 항상 가능합니다. 로그인 선택·회원가입·얼굴 촬영 화면에서는 포즈 방식을 상체로 두어 손 가리키기와 촬영에 웹캠을 씁니다.

**회원가입**(`MenuPage.SignUp`, `SignUpScreen`/`SignUpFlow`)은 단계형입니다.
1. 저장 동의: 얼굴 특징값, 닉네임, 설정(몸무게·기본 방식), 플레이 기록을 저장하고 얼굴 사진은 저장하지 않는다고 안내합니다.
2. 닉네임: 1~10자(앞뒤 공백 제거, 제어문자 금지). 다음(또는 Enter)을 누르면 서버 `/name-check`로 바로 확인하고, 사용할 수 없으면 사유를 표시합니다.
3. 몸무게·기본 방식: 몸무게는 비우면 65kg, 입력하면 10~350kg입니다. 건너뛰기는 65kg·전신을 씁니다.
4. 얼굴 촬영: 얼굴 촬영 화면에서 `/enroll`을 호출합니다. 실패하면 앞 단계 입력을 그대로 둔 채 촬영만 다시 합니다. 성공하면 회원으로 로그인하고 메인으로 갑니다(튜토리얼 제안은 이후 작업).

"이전"으로 한 단계씩 돌아가고, 동의 단계의 "돌아가기"는 로그인 선택으로 갑니다. 메인 메뉴 위쪽에는 회원이면 "OOO님", 게스트면 "게스트"를 표시합니다. "게임 시작"은 닉네임을 묻지 않고 바로 준비 화면을 엽니다.

준비 화면에서 플레이 방식과 칼로리 목표를 선택합니다. 키보드에서는 목표 입력을 비활성화하고 운동량을 적립하지 않는다고 안내합니다. 얼굴 촬영 화면(`IdentityScreen`)은 얼굴 로그인과 회원가입이 함께 쓰며, 촬영 버튼과 돌아가기만 있습니다. 로그아웃은 메인 메뉴에서 합니다(얼굴·기록 삭제는 이후 "내 정보"로 옮깁니다). 로그인 캠은 몸 골격과 몸동작 상태 없이 영상만 보여 주고, 가운데에 고정된 타원 얼굴 가이드 틀(바깥은 어둡게)과 "틀 안에 얼굴을 맞춰 주세요" 안내를 그립니다. 인식 중에는 틀이 금색으로 바뀌고 "가만히 계세요"를 표시합니다. 손 가리키기 선택은 그대로 동작합니다. 원격 서버 주소 설정은 [서버 안내](../Services/Identity/README_DOCKER.md)를 따릅니다. 얼굴이 없어도 키보드·몸동작으로 플레이할 수 있습니다.

화면은 나무·금색 팔레트와 Black Han Sans 제목 글꼴을 사용합니다. 손 가리키기/유지 선택을 메뉴·상점·랭킹 버튼에 연결했습니다. 플레이 HUD는 오른쪽 위에 거리·최고 기록·운동 모드의 현재/목표 칼로리를 모으고, 그 옆에 일시정지를 표시합니다. 코인은 왼쪽 위에 표시합니다. 활성 아이템만 작은 타이머를 표시합니다. 큰 중앙 거리·상시 속도·구간 바·반복 조작 설명·별도 얼굴 사진은 제거했습니다.

하단 안내는 한 번에 하나만 표시합니다. 인식 복구 → 가까운 장애물 → 갈림길 선택 → 경찰 → 잠깐의 콤보/구간 전환 순서로 선택합니다. 잠깐의 포즈 누락은 무시하고 0.75초 이상 인식이 끊길 때 복구 안내와 가능한 경우 미리보기를 표시합니다. 정상 추적 중에는 웹캠 미리보기를 숨깁니다. 상세 거리·최고 기록·기준 속도·구간·칼로리는 일시정지에서, 동작별 기록은 결과에서 확인합니다. 키보드 결과에는 계산하지 않은 칼로리 목표/동작별 0값을 나열하지 않습니다.

## 데이터 저장 범위

| 저장 위치 | 내용 |
| --- | --- |
| 게임 PC `Player/profile.json`, `wallet.json` | 예전 PC 프로필과 지갑. 개발자/전시 모드에서만 읽고, 일반 플레이에서는 읽지 않습니다(지우지 않음) |
| 게임 PC `Player/records.json` | 거리 기준 최대 500개 기록과 누적 통계 |
| 연결된 얼굴 서버 PostgreSQL | 회원 계정(닉네임·몸무게·기본 방식·목표·코인·해금)·세션·회원 운동 기록 |
| 게임 메모리 `AccountSession` | 지금 플레이하는 회원 또는 게스트. 게스트 설정은 게임을 끄면 사라집니다 |

PC JSON은 Unity의 `Application.persistentDataPath/Player` 아래에 있습니다. 현재 플레이어는 `AccountSession` 한 곳에서만 읽습니다. 얼굴 로그인한 회원은 서버 닉네임을 쓰고, 코인과 해금은 회원 계정에만 쌓입니다. 회원 판은 서버(`/runs`, 모드·코인 포함)와 이 PC 랭킹(회원 ID 포함)에 함께 기록하고, 서버 저장이 실패하면 메모리에 보관했다가 다음 판 저장 때 한 번 다시 보냅니다. 게스트는 "게스트" 이름으로 이 PC 랭킹에만 기록되며 코인이 쌓이지 않고 아이템도 나오지 않습니다. 게임을 끄면 회원은 로그아웃합니다(자동 로그인 없음).

기존 `Exhibition/progress.json`과 `ranking-*.json`은 새 Player 파일이 없을 때 한 번 읽어 코인·해금·거리 기록을 이전합니다. 원본을 수정/삭제하지 않습니다. 예전 순위에는 칼로리 값이 없으므로 이전 통계에 임의로 추가하지 않습니다. 실제 사용자 데이터로 이전을 실행한 검증이 아니라 임시 파일을 사용한 검증입니다.

## 개발자/전시 모드

타이틀·메뉴에서 **Ctrl+Shift+F12**로 전환합니다. Windows 관리자나 서버 DB 관리자 권한과는 별도인 게임 운영 옵션입니다.

| 항목 | 일반 | 개발자/전시 |
| --- | --- | --- |
| 이름 | 회원 닉네임 또는 "게스트" | 준비 화면에서 판마다 입력(회원은 닉네임) |
| 아이템 | 회원이 상점에서 해금한 것만(게스트 없음) | 모두 사용 |
| 코인 | 회원 계정에 적립(게스트 없음) | 적립 없음 |
| 랭킹 메뉴 | 전체 탭 | 오늘 탭 |
| 결과 버튼 | 다시 / 메인으로 | 다시 / 다음 플레이어 |
| Ctrl+F10 | 비활성 | 오늘 PC 기록 초기화 |

결과의 "다음 플레이어"는 회원을 로그아웃하고 캐릭터 사진을 해제한 뒤 로그인 선택 화면으로 갑니다.

## 코드와 검수

`HUDPresenter`가 MenuPage(로그인 선택·회원가입·얼굴 촬영 포함)를 전환하고, `Overlay/`가 메뉴·상점·프로필·랭킹·작은 거리계를 그립니다. `RunHudModel`이 프레임당 한 번 상태를 갱신하고 장애물 검색을 0.1초 간격으로 제한합니다(차선/수레 전환은 즉시). 화면 장식은 Repaint에서만 그립니다. `AccountSession`이 현재 플레이어(회원/게스트)를, `PlayerProgressStore`가 이 PC 랭킹·통계와 개발자 모드 지갑을, `LocalProfileClient`(`IAccountGateway`)가 얼굴 촬영과 계정 API를 담당합니다.

자동 검수는 개발 빌드에서 아래 플래그를 명시할 때만 실행됩니다. 실제 프로필과 카메라 대신 별도 폴더/합성 데이터를 사용합니다.

```text
Mongscape.exe --muhanok-uicapture --mongscape-tests --muhanok-out <캡처 폴더> --muhanok-data <임시 데이터 폴더>
```

검증 범위와 출처 커밋은 [통합 보고서](reports/MUHANOK_TEST_MERGE_2026_10_26.md)에 있습니다.

이후 HUD 정리와 성능 측정은 [HUD 검수 보고서](reports/HUD_POLISH_2026_10_26.md)를 확인하세요. UI 캡처의 Workout/Tracking Synthetic 화면은 합성 상태이며 실물 웹캠 검증과 구분합니다.

세 갈래 철로는 회차 내 96~120m에서 선택하고 144m부터 다음 맵 입구로 연결됩니다. 갈림길은 48m이며, 확정 후 긴 직선 구간을 제거했습니다. [경로 검수](reports/FORK_SHORT_2026_10_26.md).

# 통합 메뉴와 플레이어 데이터

`lilohdong/muhanok-test`의 기본 main 브랜치 `b2215ef`를 기존 Mongscape 소스에 통합한 화면입니다. 기존 얼굴 로그인·칼로리 목표·갈림길·경찰 연출·PostgreSQL 연결을 유지합니다.

## 화면 흐름

```text
타이틀 → 로그인 선택
          ├ 얼굴 로그인 → 얼굴 촬영 ───────────────────────────────→ 메인 ("OOO님")
          ├ 회원가입 → 저장 동의 → 닉네임(중복 확인) → 몸무게·기본 방식(건너뛰기 가능)
          │          → 얼굴 촬영 → 가입 완료 + 자동 로그인 → 튜토리얼 제안 → 메인 ("OOO님")
          └ 게스트 플레이 ──────────────────────────────────────→ 메인 ("게스트")
메인 메뉴
          ├ 게임 시작 → (튜토리얼 제안, 세션당 1회) → 탈출 준비(방식·목표) → 로딩 → 플레이
          ├ 튜토리얼 → 로딩 → 튜토리얼 코스 → 완료 → 메인
          ├ 점수 랭킹([회원 랭킹 | 이 PC] × [전신 | 상체 | 키보드] × [전체 | 오늘])
          ├ 코인 상점(회원 구매 / 게스트는 보기만)
          ├ 내 정보(회원만): 닉네임·몸무게·방식·목표, 기록 요약, 로그아웃, 탈퇴
          ├ 로그아웃(회원) / 로그인 / 회원가입(게스트) → 로그인 선택
          ├ 설정
          └ 종료
플레이 → 일시정지: 계속 / 설정 / 메인으로(기록 없이 종료)
플레이 → 결과: 점수·내 최고 기록(회원, 방식별)·신기록 여부·플레이 시간·거리·코인·최고 콤보·모드별 점수 랭킹·칼로리 패널·동작별 기록(게스트는 닉네임 [저장] / [건너뛰기]) → 다시 / (카메라 모드) 웹캠 보정 / 메인으로
```

타이틀에서 입력하면 메인 메뉴 대신 **로그인 선택**(`MenuPage.Login`, `LoginGateScreen`)이 열립니다. 버튼은 마우스 클릭, 숫자키 1~3, 손 가리키기(0.9초 유지)로 고릅니다. 화면이 열릴 때마다 얼굴 서버(`GET /health`)를 확인하고, 응답이 없거나 오류이면 얼굴 로그인·회원가입 버튼을 비활성화하고 사유를 표시합니다. 게스트 플레이는 항상 가능합니다. 로그인 선택·회원가입·얼굴 촬영 화면에서는 포즈 방식을 상체로 두어 손 가리키기와 촬영에 웹캠을 씁니다.

**회원가입**(`MenuPage.SignUp`, `SignUpScreen`/`SignUpFlow`)은 단계형입니다.
1. 저장 동의: 얼굴 특징값, 닉네임, 설정(몸무게·기본 방식), 플레이 기록을 저장하고 얼굴 사진은 저장하지 않는다고 안내합니다.
2. 닉네임: 1~10자(앞뒤 공백 제거, 제어문자 금지). 다음(또는 Enter)을 누르면 서버 `/name-check`로 바로 확인하고, 사용할 수 없으면 사유를 표시합니다.
3. 몸무게·기본 방식: 몸무게는 비우면 65kg, 입력하면 10~350kg입니다. 건너뛰기는 65kg·전신을 씁니다.
4. 얼굴 촬영: 얼굴 촬영 화면에서 `/enroll`을 호출합니다. 실패하면 앞 단계 입력을 그대로 둔 채 촬영만 다시 합니다. 성공하면 회원으로 로그인하고 튜토리얼을 제안합니다("나중에 하기"는 메인으로).

"이전"으로 한 단계씩 돌아가고, 동의 단계의 "돌아가기"는 로그인 선택으로 갑니다. 메인 메뉴 위쪽에는 회원이면 "OOO님", 게스트면 "게스트"를 표시합니다. "게임 시작"은 닉네임을 묻지 않고 준비 화면을 엽니다. 튜토리얼을 마치지 않은 회원과 모든 게스트에게는 그 전에 한 번(로그인 세션당 1회) 튜토리얼을 제안합니다(`MenuPage.TutorialOffer`, 1/Enter 시작, 2/Esc 건너뛰기, 손 가리키기 0.9초).

준비 화면에서 플레이 방식과 칼로리 목표를 선택합니다. 키보드에서는 목표 입력을 비활성화하고 운동량을 적립하지 않는다고 안내합니다. 얼굴 촬영 화면(`IdentityScreen`)은 얼굴 로그인과 회원가입이 함께 쓰며, 촬영 버튼과 돌아가기만 있습니다. 로그아웃은 메인 메뉴와 내 정보에서, 탈퇴는 내 정보에서 합니다. 로그인 캠은 몸 골격과 몸동작 상태 없이 영상만 보여 주고, 가운데에 고정된 타원 얼굴 가이드 틀(바깥은 어둡게)과 "틀 안에 얼굴을 맞춰 주세요" 안내를 그립니다. 인식 중에는 틀이 금색으로 바뀌고 "가만히 계세요"를 표시합니다. 손 가리키기 선택은 그대로 동작합니다. 원격 서버 주소 설정은 [서버 안내](../Services/Identity/README_DOCKER.md)를 따릅니다. 얼굴이 없어도 키보드·몸동작으로 플레이할 수 있습니다.

화면은 나무·금색 팔레트와 Black Han Sans 제목 글꼴을 사용합니다. 손 가리키기/유지 선택을 메뉴·상점·랭킹 버튼에 연결했습니다. 플레이 HUD는 오른쪽 위에 점수(가장 크게)와 그 아래 거리·최고 기록(회원의 현재 방식 최고 점수, 게스트는 거리만), 운동 모드의 현재/목표 칼로리를 모으고, 그 옆에 일시정지를 표시합니다. 코인은 왼쪽 위에 표시합니다. 활성 아이템만 작은 타이머를 표시합니다. 큰 중앙 거리·상시 속도·구간 바·반복 조작 설명·별도 얼굴 사진은 제거했습니다.

하단 안내는 한 번에 하나만 표시합니다. 인식 복구 → 가까운 장애물 → 갈림길 선택 → 경찰 → 잠깐의 콤보/구간 전환 순서로 선택합니다. 전신·상체 모드에서는 우측 하단에 웹캠 화면(영상과 골격, 약 200×150)을 항상 표시하고, 설정 → 표시 → 플레이 중 웹캠 화면으로 끌 수 있습니다. 키보드 모드에서는 표시하지 않습니다. 잠깐의 포즈 누락은 무시하고 0.75초 이상 인식이 끊기면 복구 안내를 띄우고 웹캠 화면을 상태 표시가 있는 복구 화면(236×174)으로 키웁니다. 점수·거리·최고 기록·플레이 시간·기준 속도·구간·칼로리는 일시정지에서, 동작별 기록은 결과에서 확인합니다. 키보드 결과에는 계산하지 않은 칼로리 목표/동작별 0값을 나열하지 않습니다.

## 점수와 칼로리

- **점수 = round(거리(m) + 점수용 칼로리 × 100)** (`Domain/WorkoutEstimate.cs`의 `RunScore`). HUD·일시정지·결과·랭킹 기록이 모두 같은 함수를 씁니다. 코인·장애물 통과·콤보는 점수에 넣지 않습니다.
- 점수용 칼로리는 입력한 몸무게와 관계없이 **65kg으로 고정**해 `MET × 3.5 × 65 / 200 × 운동초 / 60`으로 계산합니다. 같은 운동이면 몸무게가 달라도 점수가 같습니다. 예: 전신 1,240m, 운동 3분 → 1,240 + 13.65 × 100 = 2,605점.
- 화면에 보이는 칼로리는 입력한 몸무게로 계산합니다. **몸무게를 비우면 65kg**으로 계산하며, 몸무게 미입력으로 칼로리를 빼는 경우는 없습니다. 키보드는 운동초가 0이라 칼로리를 계산하지 않고 점수 = 거리입니다.
- 운동초는 카메라 모드에서 인식되고 실제 운동 동작이 감지된 시간만 셉니다. 플레이 시간(`RunSession.Elapsed`, 일시정지 제외)은 결과·일시정지에 `플레이 3:12`처럼 표시만 하고 점수와 관계없습니다.
- 결과 화면 제목 숫자는 점수이고, 플레이 시간·거리·코인·최고 콤보는 요약 줄에 둡니다.
- 랭킹은 점수로 정렬하고 동점이면 먼저 세운 기록이 앞입니다. 기록에는 `ScoreVersion`(현재 2)을 저장하며, 이전 공식 기록(필드가 없으면 1)은 지우지 않고 보관하지만 순위에는 넣지 않습니다.

## 랭킹 · 칼로리 · 내 최고 기록

```text
┌ 결과 ───────────────────────────────────────────────────┐
│ 2,605점  (내 최고 2,420점)            [신기록!]               │
│ 플레이 3:12 · 거리 1,240m · 코인 +34 · 최고 콤보 12            │
│ [회원 랭킹][이 PC]  [전신][상체][키보드]  [전체][오늘]          │
│  1. ...   2. ...   3. ...        ┌ 칼로리 ────────────┐    │
│  ...                             │ 이번 판   18.4kcal   │    │
│  ▶ 내 기록 7위                    │ 오늘 합계 52.1kcal   │    │
│                                  │ 누적 합계 310kcal    │    │
│ (게스트) 닉네임: [______] [저장] [건너뛰기]                   │
│ [다시]  [웹캠 보정](카메라 모드)  [메인으로]                  │
└─────────────────────────────────────────────────────────┘
```

- **탭**(결과·메뉴 공통, `RankingBoard`/`LeaderboardScreen`): [회원 랭킹 | 이 PC] × [전신 | 상체 | 키보드] × [전체 | 오늘]. 마우스와 손 가리키기로 고릅니다.
  - 회원 랭킹: 서버 `/leaderboard`(모드·오늘). 응답 전에는 "불러오는 중", 실패하면 "서버에 연결할 수 없어요". 회원이면 응답의 `me`로 "▶ 내 기록 N위"를 표시합니다. 게스트도 볼 수 있습니다.
  - 이 PC: `Player/records.json`의 해당 모드 기록. 회원 판은 이름 뒤에 "· 회원"을 붙입니다. 방금 판은 "▶ 내 기록" 줄로 강조합니다.
  - 결과 기본값: 회원은 회원 랭킹, 게스트는 이 PC. 모드는 방금 플레이한 방식, 기간은 오늘. 메뉴는 회원이면 회원 랭킹, 아니면 이 PC이고 모드는 기본 방식입니다(개발자 모드는 오늘 탭).
- **이 PC 랭킹 기록**(`RankingEntry`)에는 `Mode`(0 전신, 1 상체, 2 키보드), `AccountId`(게스트는 빈 값), `Kcal`을 저장합니다. `Mode`가 없는 예전 기록은 `Style` 라벨("전신"/"상체"/"키보드")로 채우고, 라벨도 없으면 -1로 두어 모드 탭에 나오지 않습니다(지우지 않음). 순위와 최대 500개 상한은 모드별입니다.
- **칼로리 패널**(결과 오른쪽): 이번 판 칼로리(키보드는 "계산 제외"). 회원은 기록이 서버에 저장된 뒤 `/stats`로 오늘 합계·누적 합계를 더합니다(받기 전 "합계 불러오는 중", 실패 시 "서버에 연결할 수 없어요"). 게스트는 이번 판만 보이고 "회원가입하면 누적 칼로리를 볼 수 있어요"를 안내합니다. 키보드 판도 회원의 합계 줄은 표시합니다. 왼쪽 "운동 기록"(최고 콤보·동작별)은 그대로입니다.
- **내 최고 기록**(회원): 로그인할 때와 판을 시작할 때 `/stats`의 모드별 `best_score`를 읽어 두고, 이번 판 저장 **전** 값과 비교합니다. 제목 옆에 "(내 최고 N점)"을, 이번 판이 더 높으면 "신기록!"을 표시합니다. HUD와 일시정지의 "최고"도 회원의 현재 방식 최고 점수입니다. 게스트는 최고 기록 대신 "회원가입하면 내 최고 기록을 볼 수 있어요"를 봅니다. 개발자 모드의 회원이 아닌 판은 이 PC에서 같은 이름·같은 방식 기록과 비교합니다.
- 결과 버튼 줄은 [다시] [메인으로](개발자 모드는 [다음 플레이어])이고, 전신·상체 판에는 가운데에 [웹캠 보정]이 더해집니다(키보드 판에는 없음).
- **웹캠 보정 패널**(`Overlay/CalibrationPanel`): 결과 화면 위에 큰 웹캠 미리보기(상태·보정 막대 포함)와 "정면에서 가만히 서 주세요", [닫기 (Esc)]를 띄우고 바로 재보정합니다. 보정이 끝나면 "보정 완료"를 1초 보여 주고 닫힙니다. 열려 있는 동안 손 가리키기는 꺼지고 결과 화면의 버튼·탭·닉네임 칸은 눌리지 않으며, Esc나 마우스로 [닫기]를 눌러야만 일찍 닫힙니다. 결과 화면을 떠나면 함께 닫힙니다. 보정이 끝난 지 60초 이내이고 그 뒤 인식이 끊기지 않았으면 [다시]로 시작하는 판은 로딩 중 재보정을 건너뜁니다([몸동작 인식](BODY_TRACKING.md#시작과-보정)).
- 이 PC의 누적 통계(`PlayerStats`)는 개발자 모드 통계로만 남습니다.

## 장애물 배치

판마다 씨드로 모든 구간의 장애물을 정합니다(`Domain/ObstacleLayout`). 같은 씨드면 같은 배치이고, 구간 순서(경로)는 고정입니다. 플레이어 판은 매번 새 씨드를, 개발용 시작은 씨드 723을 씁니다.

- 첫 구간: 점프 줄(나무 상자)과 숙이기 줄(파이프) 중 하나만 랜덤으로 남깁니다.
- 걷는 구간: 운동 줄마다 켤지 랜덤으로 정하고 최소 1줄은 켭니다. 계단의 무릎 높이 계단과 닫히는 입구 문은 지형이라 항상 켭니다. 운동 줄이 없는 줄에는 확률(`ObstacleChance`)로 레인 하나만 막는 장애물을 놓습니다(감옥 복도 문 포함).
- 확장 경로의 광산·복도·동물원 구간은 일부를 레인 막이로 바꾸고, 바나나 줄과 레인 막이는 한 레인을 항상 비웁니다.
- 광산 철로: 끊김 2곳(z 8, 18)마다 없음/왼쪽/오른쪽을 정하고 구간당 최소 1곳은 끊습니다. 갈림길 구간은 끊지 않습니다. 다리 메시는 두 곳 모두 레일 없이 구워 두고, 끊기지 않는 쪽에는 같은 크기·재질의 레일 조각을 켭니다. 끊긴 쪽에는 매달린 레일과 반대쪽을 가리키는 표지판을 켜고, 기울이기 안내도 같은 방향을 따릅니다.
- 안전 규칙: 어떤 줄도 세 레인을 모두 막지 않습니다(운동 줄은 동작으로 통과). 구간 이음새 앞뒤 4m 안에는 장애물을 두지 않습니다(지형 제외). 서로 다른 동작이 필요한 장애물은 6m 이상 띄웁니다.

## 아이템

상점에서 해금한 아이템만 걷는 구간에 나옵니다(청크마다 35%). 아이템은 단일 레인 장애물이 있는 레인과 바나나 줄을 피해 놓습니다. 다시 먹으면 지속시간이 처음 값으로 돌아갑니다.

| 아이템 | 지속 | 효과 | 표시 |
| --- | --- | --- | --- |
| 자석 | 8초 | 앞 8m 안의 코인을 레인과 관계없이 끌어와 0.8m 안에서 획득 | 캐릭터 주변을 도는 빨간 점 |
| 코인 2배 | 10초 | 코인 1개를 먹을 때 2개 적립(저장값 `DoubleScore` 유지) | HUD 코인 숫자 옆 "×2" |
| 보호막 | 15초 | 충돌 또는 미끄러짐(바나나·물웅덩이) 한 번을 막고 사라짐. 바나나 횟수가 늘지 않아 추격도 시작되지 않음. 레일 끊김은 막지 않음 | 반투명 보호막, 막는 순간 커지며 사라짐 |

끌려간 코인은 청크가 풀로 돌아가 다시 준비될 때 원래 위치로 돌아갑니다.

## 내 정보 · 상점 · 게스트 닉네임

**내 정보**(`MenuPage.Profile`, `ProfileScreen`/`ProfileForm`)는 회원에게만 메뉴 항목이 보입니다. 게스트가 이 화면을 열면 메인으로 돌아갑니다.
- 닉네임(1~10자)·몸무게(비우면 65kg)·기본 방식·칼로리 목표를 [저장](Enter)하면 `/profile/update` 한 번으로 보냅니다. 닉네임은 바뀐 경우에만 보내고, 중복(409)이면 사유를 표시하며 세션은 바뀌지 않습니다.
- 기록 요약은 `/stats`의 오늘·누적 소모 칼로리와 모드별(전신·상체·키보드) 최고 점수입니다.
- [로그아웃]은 로그인 선택으로 갑니다. [회원 탈퇴]는 두 번 확인(계속 → 탈퇴하기, 두 버튼은 서로 다른 자리)한 뒤 `/delete`를 보내고, 성공하면 이 PC 랭킹의 그 회원 기록도 지우고 게스트로 로그인 선택에 돌아갑니다. Esc는 확인 취소 또는 뒤로입니다.

**상점**: 회원은 계정의 코인과 해금 목록을 보고 `/shop/buy`로 삽니다. 성공하면 응답의 잔액·해금 목록을 반영하고, 코인 부족·이미 해금 같은 거절 사유를 표시합니다. 게스트는 아이템·효과·가격만 보고 구매 버튼 대신 "회원가입하면 코인을 모아 아이템을 해금할 수 있어요"를 봅니다. 개발자 모드는 지금처럼 모든 아이템이 해금된 PC 지갑을 보여 줍니다.

**게스트 닉네임**: 게스트 판은 끝날 때 이 PC 랭킹에 "게스트"로 먼저 기록됩니다. 결과 화면에 "이 PC 랭킹에 남길 닉네임" 칸과 [저장](Enter) [건너뛰기](Esc)가 나오고, 저장하면 그 기록의 이름만 바꿉니다(최대 10자, 새 기록을 만들지 않음). 버튼은 손 가리키기로도 누를 수 있습니다. 다음 판은 다시 "게스트"로 시작합니다. 회원과 개발자 모드 게스트("플레이어 N")에게는 입력 칸이 나오지 않습니다.

## 데이터 저장 범위

| 저장 위치 | 내용 |
| --- | --- |
| 연결된 얼굴 서버 PostgreSQL | 회원 계정(얼굴 특징값·닉네임·몸무게·기본 방식·목표·코인·해금)·세션·회원 운동 기록. 사진은 저장하지 않습니다. 탈퇴하면 모두 삭제됩니다 |
| 게임 PC `Player/records.json` | 이 PC 랭킹(모드별 점수 기준 최대 500개, 이전 공식·모드 미분류 기록은 순위 밖에 보관, 기록마다 모드·칼로리)과 누적 통계(개발자 모드 통계). 회원 판(회원 ID 포함)과 게스트 판(결과 화면에서 정한 닉네임 또는 "게스트") |
| 게임 메모리 `AccountSession` | 지금 플레이하는 회원 또는 게스트. 게스트 설정은 게임을 끄면 사라지고, 게스트에게는 코인·해금이 없습니다 |
| 게임 PC `Player/profile.json`, `wallet.json` | 예전 PC 프로필과 지갑. 개발자/전시 모드에서만 읽고, 일반 플레이에서는 읽지 않습니다(지우지 않음) |

PC JSON은 Unity의 `Application.persistentDataPath/Player` 아래에 있습니다. 현재 플레이어는 `AccountSession` 한 곳에서만 읽습니다. 얼굴 로그인한 회원은 서버 닉네임을 쓰고, 코인과 해금은 회원 계정에만 쌓입니다. 회원 판은 서버(`/runs`, 모드·코인·점수 버전 2·일시정지를 뺀 플레이 시간 포함)와 이 PC 랭킹(회원 ID 포함)에 함께 기록하고, 서버 저장이 실패하면 메모리에 보관했다가 다음 판 저장 때 한 번 다시 보냅니다. 게스트는 이 PC 랭킹에만 기록되며("게스트"로 먼저 남기고 결과 화면에서 이름을 바꿀 수 있음) 코인이 쌓이지 않고 아이템도 나오지 않습니다. 게임을 끄면 회원은 로그아웃합니다(자동 로그인 없음). 회원 요청이 401(서버 세션 만료)을 받으면 이 PC에서만 로그아웃하고(`/logout` 없음) "로그인이 만료되었어요. 다시 로그인해 주세요."와 함께 로그인 선택으로 갑니다. 판 진행 중이거나 결과 화면이면 메뉴로 돌아온 뒤에 처리하며, 저장하지 못한 판은 위 규칙대로 같은 회원이 다시 로그인한 다음 판에 한 번만 다시 보냅니다.

기존 `Exhibition/progress.json`과 `ranking-*.json`은 새 Player 파일이 없을 때 한 번 읽어 코인·해금·거리 기록을 이전합니다(이전 기록은 점수 버전 1이라 순위에는 나오지 않습니다). 원본을 수정/삭제하지 않습니다. 예전 순위에는 칼로리 값이 없으므로 이전 통계에 임의로 추가하지 않습니다. 실제 사용자 데이터로 이전을 실행한 검증이 아니라 임시 파일을 사용한 검증입니다.

## 개발자/전시 모드

타이틀·메뉴에서 **Ctrl+Shift+F12**로 전환합니다. Windows 관리자나 서버 DB 관리자 권한과는 별도인 게임 운영 옵션입니다.

| 항목 | 일반 | 개발자/전시 |
| --- | --- | --- |
| 이름 | 회원 닉네임 또는 "게스트" | 준비 화면에서 판마다 입력(회원은 닉네임) |
| 아이템 | 회원이 상점에서 해금한 것만(게스트 없음) | 모두 사용 |
| 코인 | 회원 계정에 적립(게스트 없음) | 적립 없음 |
| 랭킹 메뉴 | 전체 탭 | 오늘 탭 |
| 결과의 내 최고 기록 | 회원만(`/stats`) | 회원은 `/stats`, 그 밖에는 이 PC의 같은 이름 기록 |
| 결과 버튼 | 다시 / (카메라 모드) 웹캠 보정 / 메인으로 | 다시 / (카메라 모드) 웹캠 보정 / 다음 플레이어 |

결과의 "다음 플레이어"는 회원을 로그아웃하고 캐릭터 사진을 해제한 뒤 로그인 선택 화면으로 갑니다.

## 튜토리얼

같은 GameScene에서 실행하는 모드입니다(`RunSession.IsTutorial`, 새 GameFlowState 없음). 단계는 플레이 방식별로 보정 → 옆으로 피하기 → 점프 → 숙이기 → 무릎 높이 → 갈림길 기울이기 → 완료이고, 키보드는 보정을 뺍니다(`Domain/TutorialScript.cs`).

- 맵: 고정 seed와 튜토리얼 전용 경로(갈림길 없는 연습 회차 + 갈림길이 있는 일반 회차, `TutorialCourse`)를 씁니다. `TutorialLayout`이 랜덤 장애물·아이템·코인·끊어진 레일을 모두 지우고 단계마다 지정한 장애물 하나(가운데 줄 막힘, 점프 줄, 숙이기 줄, 계단 하이니 줄)만 둡니다.
- 진행: `TutorialDirector`가 장애물 앞에서 속도를 줄이고 큰 안내(`ActionCuePresenter`)를 띄웁니다. 맞는 동작을 하면 다시 달리고, 장애물 `Passed`(갈림길은 왼쪽/오른쪽 선택 확정)로 단계를 완료합니다.
- 실수: 잡히지 않고 "다시 해 볼까요?"를 보여 준 뒤 그 단계 앞에서 다시 시작합니다.
- 완료: 회원이면 `/profile/update`로 `tutorial_done=true`를 저장하고 메인으로 돌아갑니다. 튜토리얼은 결과 화면이 없고 랭킹·코인·칼로리에 기록하지 않으며 아이템을 놓지 않습니다.

## 코드와 검수

`HUDPresenter`가 MenuPage(로그인 선택·회원가입·얼굴 촬영 포함)를 전환하고, `Overlay/`가 메뉴·상점·내 정보·랭킹(탭·내 최고 기록·칼로리 패널 상태 `RankingBoard`, 결과의 게스트 닉네임 칸 `GuestNameRow`, 웹캠 보정 패널 `CalibrationPanel` 포함)·작은 거리계를 그립니다. `RunHudModel`이 프레임당 한 번 상태를 갱신하고 장애물 검색을 0.1초 간격으로 제한합니다(차선/수레 전환은 즉시). 화면 장식은 Repaint에서만 그립니다. `AccountSession`이 현재 플레이어(회원/게스트)를, `PlayerProgressStore`가 이 PC 랭킹·통계와 개발자 모드 지갑을, `LocalProfileClient`(`IAccountGateway`)가 얼굴 촬영과 계정 API를 담당합니다.

자동 검수는 개발 빌드에서 아래 플래그를 명시할 때만 실행됩니다. 실제 프로필과 카메라 대신 별도 폴더/합성 데이터를 사용합니다.

```text
Mongscape.exe --muhanok-uicapture --mongscape-tests --muhanok-out <캡처 폴더> --muhanok-data <임시 데이터 폴더>
```

# 칼로리 HUD · 철로 선택 · 손 메뉴 · PC 성능 조절

기준일: 2026-10-26. 기존 개인 공개 릴리스 이후의 로컬 변경입니다. 이번 변경으로 Git 커밋·푸시나 릴리스를 새로 게시하지 않았습니다. 외부 서버 배포도 별도입니다.

## 적용한 동작

- 오른쪽 위 거리·최고 기록 아래에 **목표 / 소모**를 두 줄로 표시합니다. 소수 목표를 잘라 버리지 않습니다. 키보드에서는 소모 0.0과 미집계 안내를 표시하며 실제 칼로리를 적립하지 않습니다. 몸무게 미입력은 소모 미확정으로 표시합니다.
- 세 갈래 철로의 각 방향에 자체 메시 화살표·목제 표지를 배치했습니다. 현재 선택은 금색 표지·레일로 강조하고 확정 뒤 다른 방향은 어둡게 표시합니다. 선택 구간에서만 세 방향 UI와 확정까지의 진행을 표시합니다. 확정 뒤에는 실제 선택한 목적지 이름을 잠깐 표시합니다.
- 96~120m 선택, 144m 입구 연결과 기존 목적지 무작위 배치·확정 뒤 레일 고정을 유지했습니다. 바닥/충돌 경로를 변경하지 않고 수레 카메라를 조금 높이고 뒤로 물려 세 레일을 읽게 했습니다. 분기 중 롤을 줄이고 조명은 가까운 카메라에 크게 걸리지 않게 앞으로 옮겼습니다.
- 손목 커서를 0.75초 머무르면 버튼을 한 번 선택합니다. 손/추적을 놓치거나 버튼을 벗어나면 즉시 취소합니다. 한 손을 유지해 갑작스러운 좌우 손 전환을 줄이고 프레임률과 독립적인 보간을 사용합니다. 신뢰도 낮은 관절, 미래/오래된 프레임은 거부합니다.
- 타이틀 시작·메뉴·일시정지·결과·UI Toolkit 설정에 손 선택을 연결했습니다. 설정은 가려진/스크롤 바깥 요소를 선택하지 않고 실제 가장 위 요소를 확인합니다. 스크롤 ↑/↓도 손으로 선택할 수 있습니다. 이름·숫자 직접 입력은 키보드를 사용합니다. 핀치·깊이 기반 직접 접촉을 구현한 것은 아닙니다.
- 설정 → 몸동작에 휴대폰 연결 안내와 카메라 재검색을 넣었습니다. 재검색은 목록뿐 아니라 실패한 카메라도 다시 시작하며 선택한 플레이 방식과 추론 제한을 보존합니다.

## 성능 조절 범위

첫 설치는 보통 화질을 기본으로 합니다. 기존 저장 설정은 유지합니다. 실행 중 자동 조절은 사용자 화질을 상한으로 렌더 스케일·그림자·SSAO·소품 거리를 최대 세 단계 낮춥니다. 활성 플레이 5초 이후 2초 구간을 사용하고 지속적인 지연만 반영합니다. 안정 상태가 20초 이어지면 한 단계 복구합니다. 일시정지·로딩·포커스를 잃은 상태는 제외합니다. 저장된 화질 값은 덮어쓰지 않습니다.

높은 완화 단계는 같은 모델과 카메라를 유지하며 추론 요청 상한을 30→20회/초로 낮춥니다. GPU Resident Drawer 모드와 SSAO가 같으면 다시 설정하지 않고, 매 프레임 철로 컴포넌트를 계층 검색하던 부분은 풀의 참조를 재사용합니다. 손 선택에서도 Rect 문자열을 매번 만들지 않습니다. 기존 HUD 문자열 캐시·안내 검색 제한·맵 풀링은 유지합니다.

모든 컴퓨터에서 같은 FPS를 보장하지 않습니다. 현재 몸동작 추론은 기존 Compute Shader 지원 GPU를 필요로 합니다. 키보드는 카메라 추론 없이 플레이할 수 있습니다. 자동 조절 규칙은 합성 프레임 시간으로 검증했고, 실제 저사양 PC에서 자동 단계가 내려가는 실측은 아직 하지 않았습니다.

## 휴대폰 카메라의 구현 경계

Windows에 웹캠으로 등록된 휴대폰 카메라를 선택하는 경로를 지원합니다. 아이폰/안드로이드 장치와 직접 USB 통신하는 자체 동반 앱이나 드라이버는 만들지 않았고 타사 앱을 자동 설치하지 않습니다. 실제 휴대폰 연결은 검증하지 않았습니다.

- 아이폰 + Windows: PC Camo Studio + iPhone Camo Camera 등의 연결 앱 경로가 필요합니다. [공식 USB 연결 안내](https://camo.com/support/camo/camo-getting-started).
- 안드로이드: 제조사가 구현한 USB 웹캠 모드가 있으면 데이터 케이블과 그 모드를 사용합니다. 없는 기종은 연결 앱/가상 웹캠 드라이버가 필요합니다. [Android UVC 설명](https://source.android.com/docs/core/camera/webcam), [Pixel 안내](https://support.google.com/pixelcamera/answer/14274129?hl=en).
- Apple 연속성 카메라는 Mac용 기능이며 Windows 게임의 직접 USB 연결 기능으로 간주하지 않습니다. [Apple 안내](https://support.apple.com/en-ie/102546).

자세한 사용법은 [몸동작 안내](../BODY_TRACKING.md), 설정 요소 이름과 기능은 [설정창 안내](../SETTINGS_UI.md)를 확인하세요.

## 검증

Unity EditMode **128/128**, PlayMode **38/38**. Windows 빌드·실제 EXE 검수·스모크 종료 코드 모두 0. 새 컴파일 오류 0개. 기존 맵 코드의 숨김/폐기 API 경고는 남습니다.

합성 손 좌표로 타이틀 → 메뉴 → 설정 → 몸동작 탭 → 휴대폰 안내를 선택했습니다. 실제 웹캠 인식 시험은 아닙니다. 합성 운동 HUD는 70kg·전신 가정·활동 60초로 소모 4.9 kcal와 목표 50 kcal를 표시합니다. 실제 사용자 운동 측정값이 아닙니다.

실측 환경: **NVIDIA GeForce GTX 1060 3GB, 1280×720**, 키보드, 카메라 프레임 0개. 화질별 네 구간을 각 7초 측정했습니다. 검수 도구는 고정 화질을 비교하기 위해 자동 화질을 적용하지 않습니다. 프레임 제한이 있는 측정이므로 성능 향상률이나 모든 사양의 성능 보장으로 해석하지 않습니다.

## 남은 실물 검수

- 실제 웹캠으로 전신/상체, 좌우 손, 낮은 조명과 가림, 일시정지와 키보드 복귀 감도 확인.
- 실제 iPhone/Android의 USB 연결·가상 웹캠 등록·회전/미러·지연·재연결 확인.
- 내장 GPU와 여러 해상도, 웹캠 추론을 켠 장시간 플레이. 이번 단일 PC 측정과 구분.
- 이전 자동 전체 메뉴 캡처의 네이티브 종료 오류와 Unity 메모리 정리 진단은 해결 완료로 표시하지 않음. 이번 검수의 종료 코드는 별도로 기록.
- 외부 Docker/PostgreSQL/HTTPS 서버와 두 PC 얼굴 로그인·기록 공유 검수.

## 사이렌 표시 복원 (2026-10-26)

HUD 간소화 중 경고 상태는 남았지만 실제 빨강·파랑 사이렌을 그리는 부분이 누락됐습니다. `RunHudModel.ShowSiren`을 안내 문구 우선순위와 분리하고 `RunHud`의 상단 중앙에 번갈아 켜지는 경광등을 복원했습니다. 바나나 접촉 후 기존 3.6초 경고와 두 번째 접촉 후 추격 상태를 따르며 일시정지·잡힘에서 숨깁니다. 기존 효과음 코드는 바꾸지 않았습니다.

이번에 관련 HUD EditMode 17/17, 실제 바나나 접촉·HUD 연결·일시정지/잡힘 PlayMode 1/1를 통과했습니다. 새 Windows 빌드·EXE 화면 검수·스모크 종료 코드는 모두 0이며 컴파일 오류는 없습니다. 전체 테스트를 다시 실행한 결과와 구분합니다. 실제 스피커 청취는 하지 않았습니다.
